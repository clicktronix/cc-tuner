# Загрузка правил репозитория через agent-rules

## Вывод

Для cc-tuner и codex-tuner подходит один универсальный навык в каждом плагине и
короткая инструкция, которую setup добавляет в корневой файл проекта. Подробные
правила остаются в существующих файлах. Навык читает их по области задачи; setup
не копирует таблицу маршрутизации и не создаёт очередной локальный skill.

Это архитектурный выбор для этих двух плагинов, а не утверждение, что один способ
подходит любому инструменту. Проверены официальные документы и первичные описания
проектов по состоянию на 9 сентября 2026 года.

## Что поддерживают инструменты

Codex собирает стартовые инструкции по цепочке от Git-корня до рабочей директории.
В каталоге приоритет имеет AGENTS.override.md, затем AGENTS.md. Эта операция не
равнозначна автоматической загрузке произвольных файлов .claude/rules при чтении
исходников. Поэтому корень должен явно требовать чтения применимых правил.
Обычная ссылка на файл не означает, что его текст уже попал в контекст. [1]

Claude Code имеет нативную загрузку .claude/rules: правила без paths загружаются
безусловно, с paths — при работе с соответствующими файлами. Поддерживаются
вложенные каталоги правил. CLAUDE.md умеет импортировать AGENTS.md через @AGENTS.md,
но такой импорт не создаёт у Codex обработчик paths. [2]

Навыки загружаются постепенно: сначала доступно описание, полный SKILL.md читается
при выборе навыка. Следовательно, навык сам по себе не заменяет обязательную
стартовую инструкцию. Плагин удобен для распространения общего поведения; копия
навыка в каждом прикладном репозитории для этого не нужна. [3]

## Как решают похожую задачу

| Подход | Пример | Польза | Цена для наших репозиториев |
| --- | --- | --- | --- |
| Генерация форматов из общего источника | Rulesync | Импорт и генерация конфигураций нескольких агентов | Появляются общий формат и генерируемые поверхности, которые нужно сопровождать |
| Синхронизация файлов и ссылок при setup | AgentSync | Настройка существующих проектов, повторное применение конфигурации | Возникает дополнительное владение ссылками и конфигурацией |
| Нативные правила плюс явное чтение | Выбранный вариант | Сохраняет существующие файлы и загрузчик Claude, закрывает пробел Codex | Чтение остаётся поведением модели, не жёсткой гарантией |

Rulesync предлагает init/import/generate и прямую конвертацию между инструментами.
AgentSync предлагает wizard для существующих файлов и apply для создания ссылок.
Это подтверждает полезность setup как места интеграции, но не требует внедрять
сторонний синхронизатор ради одного пробела в загрузке. [4][5]

Исследование Gloaguen et al. не обнаружило общего улучшения успешности задач от
контекстных файлов, при этом средняя стоимость inference выросла более чем на 20%.
Авторы отдельно отмечают пользу описания нестандартных практик. Это результат их
выборки, не измерение наших плагинов: он поддерживает осторожность к разрастанию
инструкций, но не доказывает эффективность предложенного навыка. [6]

## Контракт реализации

В обоих плагинах agent-rules читает инструкции целевого репозитория, применимые
правила и связанные контракты. Индекс служит навигацией, но не закрытым списком:
навык также смотрит фактический каталог и frontmatter, чтобы новая запись не
потерялась из-за устаревшей таблицы. При расширении задачи выбор повторяется.

Установщик добавляет один общий блок agent-rules в начало эффективного корневого AGENTS.md
или AGENTS.override.md. Это сохраняет блок перед большим текстом проекта: хвост
может быть обрезан лимитом Codex (по умолчанию 32 KiB). Блок остаётся понятным и без плагина. check ничего не пишет;
install сохраняет существующий текст и права файла, использует временный файл и
замену, повторный запуск не меняет файл. Различающийся блок, неоднозначные маркеры
и symlink требуют разбора владельца; автоматической перезаписи нет.

cc-tuner:setup получает локальный шаг и режим install agent-rules, который не
требует GitHub, доски или companion-плагинов. codex-tuner получает setup с явно
ограниченной ответственностью за загрузку правил. Настройки пользователя,
CLAUDE.md, hooks и исходные rules установщик не изменяет. Нативный загрузчик Claude
продолжает работать; готовность существующего импорта CLAUDE.md не заявляется.

В двух независимых пакетах общий блок, навык и helper поставляются одинаковыми
копиями. Это граница упаковки, не новый канон правил проекта. При дальнейших
изменениях их надо проверять вместе; отдельная общая runtime-зависимость сейчас
добавила бы больше сложности, чем устранила.

## Проверка и ограничения

Проверки установщика выполняются в настоящих временных Git-репозиториях: отсутствие
записи в check, повторный install, сохранение CRLF и прав, сохранение правил и
старых навыков, override, конфликты, symlink, вложенная директория и отдельный
worktree. Дополнительно выполняются штатные тесты обоих плагинов.

Эти проверки доказывают файловое поведение, но не соблюдение инструкций моделью.
Для проверки поведения полезен новый сеанс с реальной задачей: правило для worker,
несвязанное правило UI, новое правило вне индекса и переход в соседний репозиторий.
Нужно наблюдать чтение полных применимых тел до правок и отсутствие лишней загрузки.
Такой LLM-eval не подменяется тестом наличия строки в SKILL.md. Механически проверяемые
инварианты остаются в тестах и линтерах самого проекта.
